# FOOD-COLLECT-001／002／003：独立采集验证

本阶段只验证本机程序能否搜索小红书并读取五篇真实笔记的文字描述；首次成功后，停止专用浏览器并再次运行，确认重启后仍可使用。未通过前，不接入美食地图、不增加每日任务或部署。

## 运行

在项目根目录执行：

```powershell
python server/food_collection_probe.py
```

默认搜索“北大附近美食”，最多检查十篇候选，保留五篇有可用店铺推荐的帖子；可用 `--query "五道口美食"` 更换关键词、`--candidates 5` 降低候选预算、`--limit 2` 降低目标数量。候选预算必须不小于目标数量，最多20；只执行一次搜索，不循环扩量。依赖本机安装的 Agent Reach（本次版本1.6.1）及其小红书渠道：`agent-reach add xiaohongshu`。安装成功不等于真实访问通过。

本机准备记录（2026-11-10）：自动依赖下载沿用系统代理时超时，直接安装同一固定版本后成功；CloakBrowser0.6.3与自动解析的Playwright1.65.0不兼容，专用环境改用Playwright1.58.0后能启动。浏览器本体使用其原安装命令下载，Ed25519签名与SHA-256校验通过；OpenCLI1.8.7、扩展1.0.27。没有修改上游源码、系统代理或用户日常浏览器，不能据此承诺其他机器同样可用。

程序固定使用独立浏览器渠道opencli，不使用聊天中的浏览器或公开搜索摘要。每次只运行一轮搜索和逐篇读取，不自动重试。报告保存到项目私有目录 `.local/food-collection/runs/`，不会写入 `site.json` 或 `public/`；不要把包含会话信息的工具配置复制到网站或提交Git。

报告包含标题、原帖链接、作者、文字描述、店名证据和以下元数据。返回可用帖子不足或调用错误均视为未通过，进程退出码为1；依赖不存在为2。无正文的有效帖子可由评论补足店名。退出码0代表达到本轮目标数量，仍须查看元数据是否缺失和内容质量。

| 字段 | 含义 |
| --- | --- |
| likes／collects／comments | 点赞／收藏／评论；各含raw原始值、value数值、approximate是否约数。1.2万记为12000且approximate=true；缺值保留null，不冒充零 |
| published_at／updated_at | 同一笔记页面状态的time／lastUpdateTime，分别归一化为带UTC时区的ISO时间；不能用编辑时间替代发布时间 |
| date_text／date_source／date_status | 保留页面日期原文、字段来源，以及发布时间known／unknown状态；不从笔记ID、相对日期或缺年份的编辑文字猜日期 |
| counts_source／collected_at | 数值来源与采集时间；采集后的互动数可能变化 |
| shops | 店名name、推荐语evidence、来源source（title／body／comment）、作者author、识别规则rule与text_only标记；评论附可用的comment_rank和is_reply，不把评论者意见写成帖子作者意见 |
| discarded | 舍弃帖子标题／链接、原因；未识别到可用推荐不等于真实店铺不存在 |

## 店铺提取与评论

采用本地保守文字规则，不需要模型密钥或外部推理服务：优先处理P序号清单、评分清单、明确推荐语与部分餐饮店名后缀，要求同段有正面描述或至少三颗星。泛指／求推荐／疑问／明确差评／部分常见菜名排除；店名必须是原文连续片段，附证据，不补全品牌、分店或地址。普通“某某好吃”句式还要求识别到餐饮／商号后缀，避免把“看着好好吃”“分享北京好吃的”前半句当店名；这会漏掉部分无后缀品牌。

标题／正文没有可保留店铺时，再通过原渠道读取最多20条顶层评论及其已加载回复；每条单独识别，不把“这家不错”等指代猜成某店。只有标签、图片无文字或求推荐的帖子仍可能因评论中的明确推荐保留；正文与评论都无可用信息则从items舍弃并写入discarded。只读取工具实际加载的评论，不保证全部评论或所有回复，也不发评论、不点赞。评论失败与无推荐分别记录，登录／风控／限流等继续停止本轮。

这是初版规则提取，无法完整理解任意自然语言、反讽或同名歧义，可能漏识别或误识别；text_only不表示真实商户、正面评价或地理位置已经独立核实。没有读取图片，不把照片里可能存在的店名当作已提取。正文已有推荐时暂不额外请求评论；不保证填满目标五篇，也不为凑数放宽规则。

2026-11-10新增的项目扩展位于server/food_opencli，不修改工具安装源码。该扩展使用同一个Agent Reach专用浏览器，通过详情页状态读取匹配笔记ID的数据；状态缺失时仅保存可见日期文字，发布时间保持未知。点赞等优先取状态，缺失时读取笔记主互动栏，避免误取评论的点赞数。

本机已注册扩展，正常采集命令不变。换电脑或移动工程后，需要先安装Agent Reach小红书通道，再在新工程根目录注册扩展（Windows）：

```powershell
$foodPluginUri = ([uri](Join-Path (Get-Location).Path 'server/food_opencli')).AbsoluteUri
& "$env:USERPROFILE/.agent-reach/tools/npm-global/opencli.cmd" plugin install $foodPluginUri
```

OpenCLI的安装位置可能因已有系统安装而不同；此处为当前本机位置。Python桥接使用uv安装的Agent Reach运行环境，默认在APPDATA/uv/tools/agent-reach，其他工具目录可通过UV_TOOL_DIR指定。插件是本地目录链接，移动后按OpenCLI说明重新注册。源码不包含登录凭据，不把node_modules或真实报告提交Git。

## 登录与失败

- 只有实际返回NEED_LOGIN时，执行 `agent-reach login xiaohongshu`，由用户本人在专用窗口登录；不索取密码或输出Cookie。登录完成后再验证原命令。
- 验证码、限流、浏览器忙或超时均停止当前尝试，根据错误和本地状态处理，不切换账号或反复请求。
- `agent-reach doctor --text` 和 `agent-reach browser status` 查看准备状态。依赖下载超时与小红书拒绝访问分别记录。
- 首轮成功后，用 `agent-reach browser stop` 关闭程序管理的浏览器，再运行同一命令；两次搜索至少间隔10秒。该操作不关闭用户日常浏览器。

## 后续边界

本阶段不验证图文图片、视频、发布时间筛选或餐馆距离。已分别读取原始发布／编辑时间，仍未加入“一周内”筛选；取不到原始时间时保持未知。关键词相关也不等于已经确认餐馆位于北大附近。
