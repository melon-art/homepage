## 怎么读更省上下文

1. 新窗口首次进入，遵循根AGENTS读取必要的全局约定和项目定位；UI任务首次读取现行设计规范。
2. 随后从本页打开对应任务单，只检查相关源码、依赖及全局任务的对应记录；不要每次扫描全仓库、读全部历史或读取其他板块的需求。
3. 已读文档没有变化时沿用已有上下文；发生全局规则或接口变更，再补读相关部分。模块任务单维护最新决定和交付摘要，不复制长篇聊天。

源码入口：[main.jsx](../../../src/explore/main.jsx)、[style.css](../../../src/explore/style.css)、[build.mjs](../../../src/explore/build.mjs)。现有子页由探索模块构建，源码范围在开发前由总控协调，不能只修改public内生成页面。

## 文档如何进入另一个窗口

- 同一目录的聊天能读取当前文件，但并行开发须隔离，避免同时改主工程。
- 本机新worktree从包含文档的本地提交创建即可，不依赖GitHub上传。已有副本停留在旧提交时，需由总控检查其改动后更新，不能整份覆盖。
- 其他电脑、云端或从GitHub克隆的环境，需要先将相应版本推送到GitHub，再拉取或重新建立副本；远端上传本身不会自动更新已有副本。
- 先核对当前副本是否存在本页与对应任务单，不能假设两个窗口的文件与聊天历史自动同步。
